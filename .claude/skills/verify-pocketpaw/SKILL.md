# verify-pocketpaw

Surface: web UI. One FastAPI app (`src/pocketpaw/dashboard.py`) serves the
dashboard SPA at `/` (`frontend/templates/base.html` + Alpine.js). Views switch
by hash (`#/chat`, `#/activity`, `#/terminal`, `#/crew`); panels such as
Settings, Skills, MCP Servers, Health open as modals from the sidebar. Chat
channels (Telegram, Discord, Slack, WhatsApp) and the CLI subcommands are other
surfaces and are not covered here.

Helper: `.claude/skills/verify-pocketpaw/scripts/verify.sh launch|doctor|cleanup`
(executable; `PORT` defaults to 8889, never 8888; `POCKETPAW_CLAUDE_SDK_CLI_PATH`
defaults to the system `claude`).

## Launch

```bash
uv sync --dev                                                  # once per checkout
bash .claude/skills/verify-pocketpaw/scripts/verify.sh launch  # PORT=8889 by default
```

What it does: refuses if a verify server is already recorded, if `PORT` is
8888 or lower, if the port is held by someone else, or if `.venv/bin/pocketpaw`
is missing. Runs `BROWSER=/usr/bin/true nohup uv run pocketpaw --port $PORT`
from the repo root (the `BROWSER` value stops the dashboard opening a tab on the
desktop), records the wrapper pid and run-id under `.verify-evidence/current/`,
then polls `server.log` for `Uvicorn running on http://127.0.0.1:<N>` and
`GET /` → 200 (up to 90 s; a cold start takes about 25 s). It records `<N>`,
not the requested port: `--port` falls back to port+1 when busy. Ready line:
`ready: http://127.0.0.1:8889 (pid N, run <run-id>, evidence <abs path>)`.

The agent backend is the Claude Code CLI (`claude_agent_sdk`); no API key is
needed for the dashboard to render. `/api/v1/health` reports `degraded` without
an Anthropic key; that is the expected state for this skill.

## Doctor

```bash
bash .claude/skills/verify-pocketpaw/scripts/verify.sh doctor
```

Read-only. Checks: recorded pid alive; every listener on the recorded port is
that pid or its child (the uvicorn process is the `uv run` child); `GET /` →
200; prints `/api/v1/health` status. Verdicts:

- `server: ... drivable:` → every mapped feature is drivable. All of them are
  read-only UI that renders without credentials.
- `not drivable here: ...` → no recorded server, the pid is gone, a foreign
  process owns the port, or `/` is not 200. Stop; do not drive an instance you
  did not start, and never point the driver at the user's own :8888.

Doctor cannot make the instance private. `get_config_dir()` is hardcoded to
`~/.pocketpaw`, so the verify server reads the user's real sessions, settings,
and tasks. Drives look; they never send a message, delete a session, run a
task, change a setting, or add a server.

## Drive

Driver: `agent-browser` (headless Chrome). Set
`AGENT_BROWSER_EXECUTABLE_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"`
first; the bundled Chrome wedges on screenshots. Then:

- `agent-browser open http://localhost:<port>/` and wait about 4 s for Alpine
  to mount; `agent-browser snapshot -i` lists controls with `@eN` refs.
- Act by accessible name, not by ref number (refs change between snapshots):
  `agent-browser find role button click --name "Settings"`. Use `click @eN`
  only right after the snapshot that produced it.
- Assert with `agent-browser snapshot -i` (roles and names) and
  `agent-browser get text body`; `agent-browser get url` confirms hash routes.
- Start every recipe with a fresh `open`: modals do not close on Escape and
  their close button has no accessible name, so an open modal blocks the next
  sidebar `find`.
- Browser pane fallback: `mcp__Claude_Browser__navigate` to the same URL, then
  `find` / `computer left_click` / `get_page_text`. It was denied for
  `localhost:8889` when this skill was generated; try it only if agent-browser
  is unavailable.

Recipes per feature are in [`features/`](features/README.md).

## Evidence

Location: `<repo>/.verify-evidence/<run-id>/` (absolute; `run-id` is printed by
launch and stored in `.verify-evidence/current/run-id`). Per drive, save:

- `<feature-id>.txt` — `agent-browser get text body` after the action, with the URL
  and feature ID on the first line.
- `<feature-id>.png` — `agent-browser screenshot <abs run-dir>/<feature-id>.png`
  (absolute path, always; relative paths land in the daemon's folder).
- `<feature-id>.snapshot.txt` — `agent-browser snapshot -i` output when the
  proof rests on roles and names (tabs, comboboxes, disabled states).
- `server.log` — written by launch automatically.

Proof standards: real user path (click the sidebar button, do not call the
API); capture the action and the resulting state, not only the final screen;
no mocks (nothing in the mapped set needs one); never report a skipped entry
point as verified through another path. Mutating features (send, run task, save
settings) are deliberately unmapped while the instance shares `~/.pocketpaw`.

## Cleanup

```bash
agent-browser close                                              # this session only, never --all
bash .claude/skills/verify-pocketpaw/scripts/verify.sh cleanup
ls .verify-evidence/<run-id>/                                    # must still list your proof
lsof -nP -iTCP:<port> -sTCP:LISTEN                               # must print nothing
```

Sends SIGTERM to the recorded wrapper pid (it propagates to uvicorn), waits up
to 15 s, SIGKILLs the wrapper and any listener whose parent is that pid, then
removes `.verify-evidence/current/` only. If the port is still held it names the
pid and leaves it: that process was not ours. Never `pkill python` or
`pkill uv`; other sessions run PocketPaw too. Run cleanup after a failed attempt
as well. `.verify-evidence/` is gitignored; copy a proof elsewhere if a PR needs
it.

## Helpers

- `scripts/verify.sh launch|doctor|cleanup` — shown above. Env: `PORT`
  (default 8889, refuses 8888 and below), `POCKETPAW_CLAUDE_SDK_CLI_PATH`
  (default `command -v claude`).

## Maintenance

The feature map goes stale as the dashboard changes. Touching a mapped feature
means updating its file under `features/` in the same PR. There is no
`/maintain-verification-skill` in this workspace yet; edit the files by hand.
