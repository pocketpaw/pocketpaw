Pocketpaw · technical overview

One place where a business and its AI staff work.

A small business buying AI today ends up with a pile of subscriptions that don't share a memory. Pocketpaw is one operating system where each capability is a verb on a shared kernel: /sites builds the storefront and staffs it with a concierge, /growth finds customers for the same business without being re-briefed. One memory, one set of agents, one approval gate.

Eight hand-built repos. The only rented layer is the model, swappable behind our own gateway — backend-agnostic by design, self-hostable by default.

The kernel

soul memory — agents remember, portably; an open protocol, not a vendor table fabric a typed ontology of the business itself — the customer's data model, not ours ripple generative UI — agent output validated against a closed verb set, mechanically instinct the approval gate — nothing irreversible happens without the owner's yes kb knowledge — everything the business knows, compiled and searchable journal the event spine — every action recorded, auditable

Verbs compound

/sites/growth /chat/agents/knowledge /studio/code/foresight …

The kernel took three years. A new verb now takes weeks, because it's assembly, not construction: /foresight (population-scale decision simulation) shipped on existing primitives; the agent that builds a site is the same one that staffs it and sells for it. These layers compose into any verb we can imagine.
