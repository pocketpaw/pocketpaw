## Overview

`AgentLoop` is the heartbeat of PocketPaw. Every inbound message — from Telegram, Discord, REST API, CLI, or A2A — flows through this loop. It is responsible for the full lifecycle of a request: intake, security screening, agent execution, response emission, memory storage, and soul observation.

## Session-Level Concurrency

Each unique `session_key` gets its own `asyncio.Lock`. This prevents concurrent messages in the same session from interleaving their responses and corrupting conversation context. The lock dict grows as sessions open and is garbage-collected by `_gc_session_locks()` after a 1-hour TTL (`_SESSION_LOCK_TTL`). Without GC, a long-running server with many unique sessions would accumulate locks indefinitely.

## Security Pipeline

Before any message reaches the agent, it passes through:
1. **Injection scanner** (`get_injection_scanner()`): Detects prompt injection attempts. Messages classified as `ThreatLevel.HIGH` are blocked with an error event; lower threats are logged.
2. **Identity reinforcement** (`_reinforce_identity()`): Every 5 messages (`_IDENTITY_REINFORCE_INTERVAL`), the full identity block is re-appended to the system prompt to prevent personality drift on long conversations.

After the agent responds, output is passed through `redact_output()` to strip any accidentally leaked credentials or PII before being written to the bus.

## Soul Integration

`AgentLoop` initialises `SoulManager` on `start()` and passes it a `PocketPawCognitiveEngine` built from the active `AgentRouter`. This means the soul's cognition pipeline — sentiment scoring, significance scoring, fact extraction, and reflection — uses the same LLM that handles conversations rather than falling back to heuristics. `_soul_observe_and_emit()` is called after each completed exchange to let the soul record the interaction.

## Auto-Learning

`_auto_learn()` extracts key facts from each exchange and stores them in the memory manager. PII scanning for memory storage is controlled by `pii_scan_memory` config — when enabled, facts that contain detected PII are dropped before storage.

## Media Path Extraction

`_extract_media_paths()` scans agent output for `<!-- media:path -->` comment tags (emitted by Claude SDK when a tool generates a file) and falls back to a path regex for backends that don't emit structured media tags. Detected media paths are attached to the outbound message so channels can render them as images or file attachments.

## Session Cancellation

`cancel_session()` signals the in-flight asyncio task for a session to stop via `cancel_task()`. The task checks the cancellation state between agent events, so long-running tool calls may not stop immediately but will not start new work.

## Known Gaps

- `_auto_learn()` uses heuristic extraction; the cognitive engine path is more accurate but only active after `SoulManager` initialises.
- Session lock GC runs every 5 minutes; between GC cycles, idle session locks accumulate.
- Media path regex fallback may produce false positives on responses that contain file path strings not generated by tools.
