## Overview

`installer/launcher/autostart.py` provides a single `AutoStartManager` class that enables or disables start-on-login for the PocketPaw desktop launcher on any supported platform. Non-technical users expect their companion app to start automatically — this module is how PocketPaw honors that expectation.

## Platform Dispatch

The class detects the platform once at construction time and dispatches to platform-specific private methods:

```python
def enable(self) -> bool:
    if self._system == "Darwin":
        return self._macos_enable()
    elif self._system == "Windows":
        return self._windows_enable()
    elif self._system == "Linux":
        return self._linux_enable()
    logger.warning("Auto-start not supported on %s", self._system)
    return False
```

The same dispatch applies to `is_enabled()` and `disable()`. Unsupported platforms log a warning and return `False` rather than raising — the user sees "auto-start not available" rather than a crash.

## macOS: launchd Plist

macOS uses launchd for login-item management. `_macos_enable()` writes a plist file to `~/Library/LaunchAgents/com.pocketpaw.launcher.plist` using Python's `plistlib`. The plist includes:

- `Label: com.pocketpaw.launcher`
- `ProgramArguments: [executable_path, ...]`
- `RunAtLoad: True`
- `KeepAlive: False` (start once, don't restart on exit)

`_macos_plist_content()` calls `get_executable_path()` to resolve the correct binary. `_macos_disable()` removes the plist file and calls `launchctl remove` to unload the agent from the running launchd.

## Windows: Registry Run Key

Windows uses `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`. `_windows_enable()` writes a `REG_SZ` value named `"PocketPaw"` pointing to the executable. `_windows_disable()` deletes the value. `_windows_is_enabled()` checks for the value's existence.

Using the current-user registry hive (rather than `HKEY_LOCAL_MACHINE`) means no administrator privileges are required — a critical requirement for a consumer app that targets non-technical users who may not have admin rights.

## Linux: XDG .desktop File

Linux uses the XDG autostart specification: a `.desktop` file at `~/.config/autostart/com.pocketpaw.launcher.desktop`. `_linux_desktop_content()` generates the standard format:

```
[Desktop Entry]
Type=Application
Name=PocketPaw
Exec=/path/to/launcher
Hidden=false
X-GNOME-Autostart-enabled=true
```

The `X-GNOME-Autostart-enabled=true` key is included for GNOME compatibility. KDE and other XDG-compliant desktops also honor the standard `.desktop` autostart spec.

## Frozen vs. Source Executable Detection

`get_executable_path()` handles two modes:

```python
def get_executable_path() -> str:
    if getattr(sys, "frozen", False):
        return sys.executable  # PyInstaller single binary
    return sys.executable  # Python interpreter — caller appends -m installer.launcher
```

For frozen builds, `sys.executable` is the packaged `.app` or `.exe`. For source runs, it's the Python interpreter, and callers are expected to append `-m installer.launcher` as the module argument. The `_is_frozen()` helper exposes the check so callers can build the correct full command string.

## Known Gaps

The Windows implementation uses `winreg` directly. If `winreg` is not available (non-CPython implementations, or running under WSL), `_windows_enable()` will raise an `ImportError` rather than failing gracefully. The macOS implementation does not verify that launchd successfully loaded the agent after writing the plist — `launchctl load` can fail silently if the plist has a syntax error generated by `plistlib`.
