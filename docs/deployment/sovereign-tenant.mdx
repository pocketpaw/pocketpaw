# Sovereign Tenant Deployment (Enterprise)

A **sovereign tenant** is a self-contained PocketPaw Enterprise install for one
organization, running on hardware you control. Everything lives on one box: the
app, its MongoDB database, Redis for resumable agent runs, and the bundled
knowledge-base binary. No external services, no shared control plane.

This is different from the [single-user self-hosting](/deployment/self-hosting)
and [Docker](/deployment/docker) guides, which cover the OSS core. The
Enterprise layer (`pocketpaw-ee`) adds authentication, multi-user workspaces,
rooms, the admin web client, and the knowledge base — and those need MongoDB and
Redis.

<Callout type="info">
  The web client is served by the app itself. There is no separate frontend
  container — the `app` service is your entire web surface.
</Callout>

## What you get

| Service | Image | Role |
|---------|-------|------|
| `app` | `Dockerfile.enterprise` | The Enterprise app + admin web UI + bundled `kb` binary |
| `mongo` | `mongo:7` | Auth, workspaces, rooms, messaging, knowledge base |
| `redis` | `redis:7-alpine` | Resumable agent runs + the Tier-2 background worker |

All three run on a private Docker network and address each other by **service
name** (`mongo`, `redis`) — not `localhost`. This is the key fix over the OSS
compose: inside a container, `localhost` is the container itself, so a
`mongodb://localhost:27017` default can never reach a Mongo running in a sibling
container.

## Quick start (Docker Compose)

From a checkout of the repository:

```bash
# 1. Create your env file from the template and fill in the required values
cp .env.enterprise.example .env
#    Edit .env: set POCKETPAW_ANTHROPIC_API_KEY. Leave the license keys for now.

# 2. Build and start the stack
docker compose -f docker-compose.enterprise.yml up -d --build

# 3. Read the one-time admin password from the logs
docker compose -f docker-compose.enterprise.yml logs app | grep -i password
```

The dashboard is now at `http://<server>:8888`. Log in with `admin@pocketpaw.ai`
(or your `ADMIN_EMAIL`) and the generated password.

<Callout type="warning">
  The image runs in **production posture** (`POCKETPAW_ENV=production`). The app
  will refuse to boot insecurely — see [Security posture](#security-posture)
  below. The two things you must do for production are: keep the
  auto-generated `AUTH_SECRET` (handled for you), and set your own license key
  (see [License hardening](#license-hardening)).
</Callout>

### What's handled for you

- **`AUTH_SECRET`** — generated and persisted on first run by the image
  entrypoint, stored on the data volume so it is stable across restarts. You
  never have to craft it. (Set it yourself in `.env` only if you want to pin or
  rotate it.)
- **Initial admin password** — generated by the app and printed once to the
  logs. The legacy `admin123` is rejected. Set `ADMIN_PASSWORD` in `.env` to
  choose your own.
- **Service URIs** — `CLOUD_MONGODB_URI`, `POCKETPAW_MONGO_URI`, and
  `POCKETPAW_REDIS_URL` are wired to the in-network service names by the compose
  file. Do not set them in `.env`.
- **The `kb` binary** — built into the image and pointed at via
  `POCKETPAW_KB_BIN`. The runtime no longer needs `kb` installed on the host.

## License hardening

PocketPaw ships a committed **DEV** license keypair so a fresh checkout can mint
and verify licenses with zero setup. That key is a **bypass** in production: its
private seed is in the repository, so anyone can forge a license your tenant
would accept. Under production posture the license layer **refuses to start** on
the DEV key — you must supply your own.

Do this once per tenant:

```bash
# 1. Generate an operator keypair (run inside the app container)
docker compose -f docker-compose.enterprise.yml \
  exec app python -m pocketpaw_ee.cloud.mint generate-keypair
# Prints:
#   PRIVATE (keep secret): <private-hex>
#   PUBLIC  (bake into POCKETPAW_LICENSE_PUBLIC_KEY): <public-hex>

# 2. Put the PUBLIC key in .env
echo 'POCKETPAW_LICENSE_PUBLIC_KEY=<public-hex>' >> .env

# 3. Mint a license with the PRIVATE key, set it as POCKETPAW_LICENSE_KEY
docker compose -f docker-compose.enterprise.yml exec \
  -e POCKETPAW_LICENSE_PRIVATE_KEY=<private-hex> app \
  python -m pocketpaw_ee.cloud.mint mint \
  --org "Your Org" --plan enterprise --seats 100 --days 365
# Copy the printed key into .env:
#   POCKETPAW_LICENSE_KEY=<minted-key>

# 4. Recreate the app so it picks up the new env
docker compose -f docker-compose.enterprise.yml up -d app
```

<Callout type="warning">
  Keep the **private** key off the server after minting. It only needs to exist
  at mint time. Store it in your secrets manager; the server only ever needs the
  **public** key (`POCKETPAW_LICENSE_PUBLIC_KEY`) and the minted
  `POCKETPAW_LICENSE_KEY`.
</Callout>

## Security posture

The Enterprise image is **secure by default** so a non-expert operator cannot
boot an ownable tenant:

- **`POCKETPAW_ENV=production`** — turns on the fail-fast gates below.
- **`AUTH_SECRET`** — the app refuses to boot if it is unset or the public
  placeholder. The entrypoint generates a strong one on first run, so this is
  satisfied automatically.
- **Admin password** — never defaults to `admin123`; it is generated and printed
  once, or you supply your own.
- **License key** — refuses to verify against the committed DEV public key in
  production (see above).
- **`POCKETPAW_LOCALHOST_AUTH_BYPASS=false`** — the localhost auth bypass is off,
  because Docker bridge traffic never appears to come from `127.0.0.1` anyway.

When you put the tenant behind HTTPS, also set `POCKETPAW_AUTH_COOKIE_SECURE=true`
in `.env`. That flag is itself a production signal, so the gates above stay
active even if you ever unset `POCKETPAW_ENV`.

## Bare-Ubuntu runbook

A from-scratch install on a fresh Ubuntu 22.04/24.04 server.

### 1. Provision the host

```bash
# As a sudo user on the fresh server
sudo apt-get update && sudo apt-get upgrade -y

# Install Docker Engine + the compose plugin
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io \
  docker-buildx-plugin docker-compose-plugin

# Let your user run docker without sudo (log out / back in after)
sudo usermod -aG docker "$USER"
```

### 2. Get the code and configure

```bash
git clone https://github.com/pocketpaw/pocketpaw.git
cd pocketpaw

cp .env.enterprise.example .env
# Edit .env: set POCKETPAW_ANTHROPIC_API_KEY (license keys come after first boot)
```

### 3. Build and launch

```bash
docker compose -f docker-compose.enterprise.yml up -d --build

# Wait for the stack to come up, then grab the admin password
docker compose -f docker-compose.enterprise.yml logs app | grep -i password
```

### 4. Harden the license

Follow [License hardening](#license-hardening) above to generate your keypair,
set `POCKETPAW_LICENSE_PUBLIC_KEY` + `POCKETPAW_LICENSE_KEY`, and recreate the
app.

### 5. Put it behind TLS

Run a reverse proxy (Caddy is simplest) on the host and point it at the app's
published port `8888`:

```
# /etc/caddy/Caddyfile
tenant.example.com {
    reverse_proxy localhost:8888
}
```

Then set `POCKETPAW_AUTH_COOKIE_SECURE=true` in `.env` and recreate the app.

<Callout type="info">
  The WebSocket connection needs the `Upgrade` / `Connection` headers proxied.
  Caddy's `reverse_proxy` handles this automatically; for nginx see the
  [self-hosting guide](/deployment/self-hosting).
</Callout>

### 6. Firewall

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

Do **not** open `8888` to the internet — only the reverse proxy should reach it.
Mongo (`27017`) and Redis (`6379`) are not published to the host at all; they
stay on the private Docker network.

## Operations

```bash
# Tail logs
docker compose -f docker-compose.enterprise.yml logs -f app

# Restart just the app (e.g. after editing .env)
docker compose -f docker-compose.enterprise.yml up -d app

# Stop everything (data survives in the named volumes)
docker compose -f docker-compose.enterprise.yml down

# Back up the database
docker compose -f docker-compose.enterprise.yml exec mongo \
  mongodump --archive --db paw-enterprise > backup-$(date +%F).archive
```

The named volumes — `pocketpaw-data`, `mongo-data`, `redis-data` — hold all
persistent state. The generated `AUTH_SECRET` lives in `pocketpaw-data`; do not
delete that volume unless you intend to rotate it (which logs everyone out).
