# Plan and organize work

**What it is.** The same Deep Work screen also groups work into projects and sprints, and can draft a plan for a project. You use these tabs to shape a body of work, not just react to one task at a time.

**When you'd use it.** Open these when you're setting up a stretch of work — grouping tasks into a sprint, or asking Paw OS by PocketPaw to break a project into tasks for you.

## Group tasks into a sprint
1. Open **Deep Work** and select the **Sprints** tab.
2. In the left rail, pick an existing sprint, or click the button to add a new one and fill in its details.
3. With a sprint selected, the main area shows the tasks in it.
4. Add work two ways:
   - Click the option to add a brand-new task — this opens the create form with the sprint already filled in.
   - Click the option to add existing tasks — this opens a picker of unsprinted tasks you can multi-select.
5. Click a task to open its detail panel, same as on the Feed.

## Draft a plan for a project
1. Select the **Plan** tab.
2. Pick a project, or generate a plan from the workspace-wide starting point.
3. Use the plan generator to turn the project into a set of draft tasks.
4. Past plan drafts appear in the left rail — click one to reopen it.
5. If the plan needs an agent that doesn't exist yet, use the **Create agent** action on the gap row to set one up without leaving the plan.

## Switch projects and scope
1. The **Projects** section sits at the top of the left rail. Click a project to filter every tab to it.
2. The toolbar trail shows your current scope: workspace, then project, then pocket.
3. To go back to everything, choose **All projects**.

## See the numbers
1. Select the **Analytics** tab for a roll-up of the current project's work.
2. Select the **Activity** tab for a running log; use the filter chips in the left rail to narrow by category, agent, or time window.

## Tips
- Filters set in the **Projects** rail follow you across the Feed, Sprints, and Analytics tabs.
- A generated plan drops you straight onto the Plan tab for that project, with its new tasks already in the feed.

## If something's off
- This planning surface looks partly wired in the current build (plan generation and sprint grouping depend on backend endpoints that may not be live everywhere). Confirm each action saves before relying on it.
- The create form labels the sprint field **Cycle**, while the tab is named **Sprints**. They refer to the same thing. Flagged for a naming fix.
- If past plan drafts don't load, the drafts list keeps whatever it already had rather than clearing — try reopening the Plan tab.
